## 三、问题清单

### P0 致命问题

### P1 高风险问题

**REVIEW-PRD-001** | P1 | 后端 PRD 包含了技术实现细节
- **问题描述**：后端 PRD 第 5.4 节「总结缓存策略」中指定了具体存储位置为 `mt_profile` 集合。PRD 应以业务语言描述"做什么/为什么"，不应包含具体集合名等实现细节。
- **影响范围**：后端 PRD 第 5.4 节
- **建议动作**：将存储位置描述改为业务规则表述，如「总结缓存存储在学习档案中，与用户信息关联」
- **是否阻断**：否

**REVIEW-PRD-002** | P1 | 「有更新」的触发条件定义不精确
- **问题描述**：后端 PRD 第 5.4 节「有新学习内容时才重新生成」中的「有新学习内容」未明确定义。用户发送一条消息算更新？完成一次完整会话算更新？掌握度发生变化算更新？
- **影响范围**：后端 PRD 第 5.4 节、小程序 PRD 第 3.5 节
- **建议动作**：明确定义触发重新生成的条件，建议为「用户完成一次完整学习会话（至少有一轮问答）后，标记总结需要更新」
- **是否阻断**：否

### P2 改进建议

**REVIEW-PRD-003** | P2 | 知识点排序责任边界未明确
- **问题描述**：后端 PRD 的 AC-5 要求「知识点列表按掌握程度从低到高排序」，但排序可由后端或前端完成，PRD 未明确由哪一端负责。
- **影响范围**：后端 PRD AC-5
- **建议动作**：明确由后端排序返回，前端直接展示（或前端排序，二选一）。建议后端排序，减少前端逻辑。
