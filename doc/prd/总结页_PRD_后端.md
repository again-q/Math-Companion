## 1. 产品背景

### 1.1 业务目标

为「数学小伴」用户提供可视化的学习历程回顾，让用户直观了解自己的学习进度、知识点掌握情况和成长轨迹，增强学习动力和成就感。

### 1.2 范围

**范围内**：
- 学习统计数据聚合（学习天数、学习次数、对话消息数、知识点数）
- 知识点掌握程度计算与等级划分
- 个性化学习建议自动生成
- AI 学习总结文字生成
- 数据范围筛选（近期 / 全部）

**范围外**：
- 实时学习数据推送（仅拉取模式）
- 知识点掌握度的外部共享

## 2. 用户与场景

### 2.1 目标用户

使用「数学小伴」微信小程序学习数学的学生用户。

### 2.2 用户场景

| 场景 | 频率 | 价值 |
|------|------|------|
| 学生想看看自己学了多少天、学了多少知识点 | 每次打开总结页 | 成就感驱动持续学习 |
| 学生想了解哪些知识点已经掌握、哪些还在学 | 每次打开总结页 | 明确学习方向 |
| 系统自动给出下一步学习建议 | 每次打开总结页 | 降低决策成本 |
| AI 老师用鼓励的语气总结近期学习表现 | 有新学习内容时 | 情感激励 |

## 3. 功能需求

### 3.1 学习数据聚合

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 学习天数统计 | 统计用户从第一次学习至今的天数 | P0 |
| 学习次数统计 | 统计用户总学习会话数 | P0 |
| 对话消息数统计 | 统计用户与 AI 的总对话消息条数 | P0 |
| 知识点数统计 | 统计用户涉及的不同知识点数量 | P0 |
| 数据范围筛选 | 支持按「近期」和「全部」两种范围获取数据 | P1 |

**验收标准**：

> **AC-1**：当用户至少有一次学习记录时，学习天数 = 从首次学习日期到今天的自然天数 + 1
>
> Given 用户第一次学习是 7 天前
> When 用户查看总结页
> Then 学习天数显示为 8 天

> **AC-2**：当用户选择「全部」范围时，返回所有历史学习数据
>
> Given 用户有 50 条学习会话记录
> When 用户切换到「全部」范围
> Then 返回全部 50 条会话的统计数据

> **AC-3**：当用户没有任何学习记录时，返回空数据状态
>
> Given 用户从未学习过
> When 用户查看总结页
> Then 学习天数为 0，学习次数为 0，知识点列表为空

### 3.2 知识点掌握度

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 知识点进度查询 | 按知识点返回掌握程度等级和练习次数 | P0 |
| 掌握等级划分 | 根据掌握程度自动分配等级描述 | P0 |

**等级描述映射**：
| 掌握程度范围 | 等级描述 |
|-------------|---------|
| < 0.3 | 初识 |
| 0.3 ~ 0.5 | 了解 |
| 0.5 ~ 0.7 | 掌握 |
| 0.7 ~ 0.9 | 熟练 |
| >= 0.9 | 精通 |

**验收标准**：

> **AC-4**：每个知识点返回其掌握程度（0~1 之间的数值）、练习次数、连续答对次数、等级文字描述
>
> Given 用户练习了「一元一次方程」5 次，掌握程度 0.65
> When 后端返回该知识点数据
> Then 包含 level=0.65, practicedCount=5, levelDesc="掌握"

> **AC-5**：知识点列表按掌握程度从低到高排序（由后端排序后返回），让用户知道哪些知识点需要加强
>
> Given 用户有 3 个知识点：A(level=0.8), B(level=0.3), C(level=0.5)
> When 后端返回知识点列表
> Then 顺序为 B(0.3) → C(0.5) → A(0.8)

### 3.3 学习建议生成

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 个性化建议 | 根据学习数据自动生成 2~4 条学习建议 | P0 |
| 里程碑识别 | 识别学习里程碑（如坚持一周、消息超 50 条）并给出鼓励 | P0 |

**验收标准**：

> **AC-6**：当用户有已掌握的知识点时，生成 1 条鼓励继续学习的建议
>
> Given 用户已掌握 3 个知识点
> When 生成学习建议
> Then 包含 1 条关于已掌握知识点的鼓励建议

> **AC-7**：当用户连续学习超过 7 天时，生成 1 条关于坚持习惯的鼓励建议
>
> Given 用户已连续学习 10 天
> When 生成学习建议
> Then 包含 1 条关于坚持习惯的建议

### 3.4 AI 学习总结（「小伴说」）

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 总结文字生成 | 根据学习数据生成一段鼓励性的学习总结 | P0 |
| 增量更新 | 仅在有新学习内容时才重新生成总结，避免重复消耗 | P1 |

**验收标准**：

> **AC-8**：总结文字包含学习天数、总消息数、知识点数量等关键数据，语气鼓励亲切
>
> Given 用户学习 15 天、对话 120 条、掌握 4 个知识点
> When 生成学习总结
> Then 总结文字中应包含以上三个数据，且语气积极鼓励

> **AC-9**：当没有新学习内容时，不重新生成总结，返回已有总结
>
> Given 上次生成总结后用户没有新的学习记录
> When 请求学习总结
> Then 返回上次已生成的总结内容

## 4. 接口定义

### 4.1 获取学习总结

获取用户的学习统计数据、知识点掌握情况、学习建议和 AI 总结文字。

**请求**：
- 方式：云函数调用
- 类型标识：`getSummary`
- 参数：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| scope | string | 否 | 数据范围：`recent`（近期，默认）/ `all`（全部） |

**响应**：

| 字段 | 类型 | 说明 |
|------|------|------|
| summary | string | AI 生成的学习总结文字，空数据时返回欢迎语 |
| topicsCovered | array | 知识点掌握列表，每个元素含 topic/level/practicedCount/consecutiveCorrect/levelDesc |
| totalSessions | number | 总学习次数（会话数） |
| totalMessages | number | 总对话消息数 |
| learningDays | number | 学习天数 |
| stats | object | 统计数据聚合，含 masteredCount/learningCount/newCount/avgLevel |
| suggestions | array | 学习建议文字列表，每条为字符串 |

## 5. 业务规则与数据规范

### 5.1 数据来源

| 数据项 | 来源集合 |
|--------|---------|
| 学习次数 | `mt_sessions` 集合，count 活跃会话数 |
| 消息数 | `mt_messages` 集合，按 sessionId 聚合 |
| 学习天数 | 从最早会话的 createdAt 到当前日期的天数差 |
| 知识点进度 | `mt_knowledge_progress` 集合 |
| 知识点掌握度 | 根据答对/答错动态调整，初始值 0.3，答对 +0.1，答错 -0.1 |
| 学习建议 | 根据统计数据和里程碑规则自动生成 |

### 5.2 空数据处理

当没有任何学习记录时，返回：
- `totalSessions = 0`
- `totalMessages = 0`
- `learningDays = 0`
- `topicsCovered = []`
- `suggestions = []`
- `summary = "小伴还没和你一起学习过呢~ 快来开始我们的第一次数学之旅吧！🐰"`

### 5.3 数据范围

- `recent`（近期）：返回最近 10 条活跃会话的数据
- `all`（全部）：返回最近 100 条活跃会话的数据

### 5.4 总结缓存策略

- 每次用户完成一次完整学习会话（至少有一轮问答互动）后，标记「总结需要更新」
- 请求总结时，检查标记；有更新则重新生成，无更新则返回上次结果
- 缓存存储在学习档案中，与用户信息关联

## 6. 非功能需求

| 需求 | 说明 | 优先级 |
|------|------|--------|
| 响应速度 | 总结页数据加载应在 3 秒内完成 | P0 |
| 并发支持 | 支持多用户同时查询总结数据 | P0 |
| 数据一致性 | 统计数据与真实学习记录保持一致，误差不超过 1 | P0 |
